使用AI工具来完成自动提交代码

2026-01-06
阅读时长: 6 分钟

背景

在日常开发工作中，git commit 和 push 是每个开发者都需要频繁执行的操作。传统的流程通常是：

  1. 查看代码变更：git status、git diff
  2. 暂存变更：git add .
  3. 编写 commit message：需要思考如何简洁准确地描述本次变更
  4. 提交代码：git commit -m "message"
  5. 推送到远程：git push

这个过程虽然不复杂，但每次都需要手动编写 commit message，有时候为了写一个合适的 commit message 还要思考半天。特别是在快速迭代开发时，频繁的提交操作会打断开发节奏。

AI 时代的到来，让这个问题有了更好的解决方案。我尝试使用 Cursor 和 Claude 这两个 AI 工具来自动化完成代码提交和推送的流程，大大提升了开发效率。

Cursor Command Push

Cursor 是我最常用的 AI 的代码编辑器，支持自定义命令（Commands）来扩展功能。我创建了一个名为 push 的命令来自动完成代码提交和推送。

命令配置

命令文件位置：~/.cursor/commands/push.md

# push

1. 根据当前的修改创建新的 commit，并将 commit 推送到远程的跟当前一致的分支。
2. git commit 内容采用中文。

这个命令的配置非常简单，主要定义了三个要点：

  • 自动分析当前修改并创建 commit
  • 推送到当前分支对应的远程分支
  • commit message 使用中文

使用方式

在 Cursor 中，只需要：

  1. 完成代码修改
  2. 在 Agent 对话框中输入 push 命令
  3. Cursor 会自动分析代码变更，生成合适的 commit message，并执行提交和推送

个人感受

该方式已经能满足我的要求，同样的方式可以用在 Qoder 中。

由于每执行一次都会消耗 Cursor 的 request，而 cursor request 相对比较珍贵，我决定寻找其他的替换方案。

# Push - 自动 Git 提交推送

一键完成代码提交和推送,无需交互。

## 核心流程

**自动化执行以下步骤,无需用户确认**:

### 1. 检查仓库状态

```bash
git status
```

### 2. 分析所有变更

```bash
# 查看未暂存的变更
git diff

# 查看已暂存的变更  
git diff --cached

# 查看文件变更摘要
git diff --stat
```

### 3. 自动生成 Commit Message

**根据变更内容自动判断类型和描述**:

- 如果新增文件较多 → `feat: 添加 <功能描述>`
- 如果修改现有文件 → `fix/refactor/feat: <变更描述>`
- 如果删除文件 → `refactor: 移除 <内容描述>`
- 如果只改文档 → `docs: 更新 <文档名称>`
- 如果改配置文件 → `chore: 更新配置`

**Commit Message 格式**: `<type>: <简洁描述>`

**Type 类型**:

- `feat` - 新功能
- `fix` - Bug 修复
- `docs` - 文档
- `style` - 格式调整
- `refactor` - 重构
- `perf` - 性能优化
- `test` - 测试
- `chore` - 构建/工具

### 4. 自动执行提交推送

```bash
# 1. 添加所有变更
git add .

# 2. 提交变更
git commit -m "<自动生成的 commit message>"

# 3. 推送到远程
git push

# 如果是新分支,使用
git push -u origin $(git branch --show-current)
```

## 执行原则

### 默认行为(无需确认)

- 提交所有变更文件(`git add .`)
- 使用自动生成的 commit message
- 直接推送到当前分支的远程

### 安全检查(静默执行)

执行前自动检查:

- ✓ 是否在 Git 仓库中
- ✓ 是否有变更需要提交
- ✓ 是否存在 .gitignore(避免提交敏感文件)
- ✓ 是否有远程仓库配置

**如遇问题才提示用户**:

- ✗ 没有变更 → 提示"工作区干净,无需提交"
- ✗ 推送失败(需要 pull) → 提示"需要先拉取远程更新"
- ✗ 有冲突 → 提示"存在冲突,请手动解决"
- ✗ 没有远程仓库 → 提示"未配置远程仓库"

## 响应模式

### 成功案例

```
✓ 分析变更: 3 个文件修改,+45/-12 行
✓ 生成 commit: "feat: 添加用户认证功能"
✓ 提交完成: 1 commit
✓ 推送成功: origin/main

完成! 代码已推送到远程仓库。
```

### 需要处理的情况

```
⚠ 检测到需要先拉取远程更新

执行: git pull --rebase
✓ 已拉取并合并远程更新
✓ 继续推送...
```

## Commit Message 生成策略

**智能分析变更内容**:

1. **检查文件类型分布**
   - README.md, docs/ → `docs`
   - package.json, Dockerfile → `chore`  
   - src/, lib/ → `feat/fix/refactor`
   - test/ → `test`

2. **检查变更模式**
   - 新增多个文件 → `feat: 添加 <模块名>`
   - 修改单个文件 → `fix: 修复 <具体问题>` 或 `refactor: 优化 <内容>`
   - 删除文件 → `refactor: 移除 <废弃内容>`

3. **分析 diff 内容关键词**
   - 包含 "TODO", "FIXME" → `fix`
   - 包含 "add", "new" → `feat`
   - 包含 "update", "improve" → `refactor`
   - 包含 "remove", "delete" → `refactor`

4. **生成简洁描述**(不超过 50 字符)
   - 使用动词开头: 添加、修复、优化、更新
   - 说明核心变更,省略细节
   - 示例: "添加用户登录功能" 而非 "添加了用户登录功能的实现代码"

## 特殊场景处理

### 首次推送新分支

```bash
# 自动检测并执行
git push -u origin $(git branch --show-current)
```

### 需要 Pull 时

```bash
# 自动执行 rebase 拉取
git pull --rebase
# 然后继续 push
git push
```

### 有未跟踪文件时

```bash
# 全部添加(除非在 .gitignore 中)
git add .
```

## 简化交互

**用户只需输入以下任一命令**:

- `push`
- `提交`
- `推送`
- `commit and push`
- `提交并推送`

**Claude 自动完成全部流程,只在必要时输出关键信息**。

## 错误处理

自动处理常见问题:

1. **远程有新提交** → 自动 `git pull --rebase`
2. **新分支无上游** → 自动 `git push -u origin <branch>`
3. **无变更** → 提示"工作区干净"并退出
4. **推送冲突** → 提示需要手动解决并停止

**只有无法自动解决的问题才会停止并提示用户**。

## 示例输出

**正常流程**(最小化输出):

```
⚡ 正在提交...
✓ feat: 添加支付接口集成
✓ 已推送到 origin/main
```

**需要处理远程更新**:

```
⚡ 正在提交...
↓ 先拉取远程更新...
✓ feat: 添加支付接口集成  
✓ 已推送到 origin/main
```

## 最佳实践

- 定期推送,保持小而频繁的提交
- 信任自动生成的 commit message(基于实际变更内容)
- 如需自定义 message,使用传统 git 命令
- .gitignore 应包含敏感文件和依赖目录

## 性能优化

- 使用 `git diff --stat` 快速获取变更摘要
- 避免执行不必要的检查
- 合并多个 git 命令减少 I/O
- 输出精简信息,减少干扰

使用方式

在 Claude 中，只需要输入以下任一命令：

  • push
  • 提交
  • 推送
  • commit and push
  • 提交并推送

Claude 会自动完成全部流程，只在必要时输出关键信息。

上述方式需要交互，还可以直接在命令行工具中执行 claude -p push 来直接提交代码，跟使用普通的 shell 命令类似。
